# FeelMuse

**开始设计流程之前，先实际读取 [interaction.md](references/interaction.md)。** 用其中的规则决定何时直接做、何时先验证、何时给出具体建议并等待用户选择。在后续方案改变时重新应用同一规则。其余文档按当前阶段读取。所有相对路径均从本 Skill 目录解析。

在终端用自然语言协作，在浏览器里看结果。开始或恢复任务时按 [progress.md](references/progress.md) 同步 CLI 进度和项目现场记录。每阶段先选一个当前最需要验证的假设，说明什么现象算通过。以下阶段用于内部判断，可以合并或回退。用户仅要求研究、建议或原型时，在对应交付点收束。

1. **Research**　了解产品、受众、访客的主要任务和已知偏好。检查项目的路由、组件、素材以及现有设计系统在代码里的实际用法。已有网站先运行，记录原始构图、品牌气质、主视觉、关键交互与需要保留的资产，留下可比较的基线。若页面打不开，获取预览或截图后再决定品牌改动。研究参考时读 [research.md](references/research.md)；多参考分别提取相关机制，只借鉴某个动效时限定研究范围。
2. **Imagine**　需要表现力的 Landing Page 先验证首屏构图、视觉焦点及有叙事作用的关键动效，推迟完整功能界面。若当前疑问是内容能否读懂或操作是否直观，则优先验证内容或交互。读 [creative-direction.md](references/creative-direction.md)。从产品内容出发提出一个具体画面，讲清作用、素材、可行性和风险。比较核心区域至少两种实质不同的表达；需要用户决定方向时，给一个有理由的推荐。
3. **Visualize & Align**　按交互规则处理首屏的重大构图选择；按 [implementation.md](references/implementation.md) 限定原型范围，用真实浏览器验证当前假设，展示实际预览或截图。需要确认首屏的任务在此等用户反馈；小改可直接用现有页面验证。仅请求方案或原型时，在该交付点停下。
4. **Define Design System**　只有方向已确认、关键画面或原型已实际验证、适用的首屏确认已完成，才读 [design-system.md](references/design-system.md)，在目标项目中建立或更新规范。从已验证的页面提炼视觉语言、组件、动效和交互规则，并落实到现有主题、Token、组件及其真实调用处。现有规范已覆盖本次需求时直接复用；验证不足时保留探索状态。
5. **Build**　按 [implementation.md](references/implementation.md) 实现。后续页面先查项目规范与代码入口，复用公共组件、导航与反馈约定，再按本页任务选择构图和叙事。遇到真正的新模式，先在局部验证其价值，再决定是否纳入系统。
6. **Review & Refine**　读 [review.md](references/review.md)。实际操作页面，分别审查功能和视觉质量；将新增或修改的页面与已验证画面对照，检查组件状态、交互反馈与跨页一致性。需要调整公共规则时同步修改规范、代码和受影响的页面，再渲染复测。交付预览、实测结果和待补素材或未验收项。
