# FeelMuse

**开始设计流程之前，先实际读取 [interaction.md](references/interaction.md)。** 用其中的规则决定何时直接做、何时先验证、何时给出具体建议并等待用户选择。在后续方案改变时重新应用同一规则。其余文档按当前阶段读取。所有相对路径均从本 Skill 目录解析。

在终端用自然语言协作，在浏览器里看结果。以下阶段用于内部判断，可以合并或回退。用户仅要求研究、建议或原型时，在对应交付点收束。

1. **Understand**　找出产品、受众、页面希望访客完成的动作，以及已知的偏好和不能改变的内容。检查现有代码、路由、启动命令、组件、素材。已有网站先启动并浏览，记录原始构图、气质、主视觉、关键交互和必须保留的辨识点，留可复查的基线。若页面打不开，说明原因并索取预览或截图，暂缓会改变品牌方向的改动。
2. **Explore**　研究参考时读 [research.md](references/research.md)。从零设计可主动找少量相关案例；多个参考分别落实到页面区域和设计机制；单一动效只研究指定部分。现站增强以原站为主要依据，避免无关的风格探索。
3. **Propose**　构思页面或交互时读 [creative-direction.md](references/creative-direction.md)。从产品自身推导一个值得推荐的画面、叙事或动作。说明它的作用、素材、实现和风险。只有真正改变用户体验的分歧才值得给出备选。
4. **Align**　应用已读的交互规则。需要选择时先给出具体建议，等答复再改正式页面。已有明确方向的局部增强可以将简短设计意图与实现合并。
5. **Build**　进入实现或试验时读 [implementation.md](references/implementation.md)。复用项目栈和素材；高风险机制先做最小可运行原型，浏览器验证后才扩展。
6. **Review**　交付实现前读 [review.md](references/review.md)。实际操作页面，自查、修正并复测；给出预览入口、观察到的结果和待替换的素材。无法浏览时明确标记未验收范围。
