# CLI 进度与跨会话恢复

开始先读目标项目根目录的 `.feelmuse/session.md`（若存在），对照最新用户要求、实际文件和预览。已确认决定继续沿用；过时记录就地更正，缺少依据的确认标为待确认。使用同一份简短快照更新当前任务相关内容，保留仍有效的决定。

读取现场后，在首次设计或编辑操作前主动显示一行：`阶段｜正在：…｜已完成：…｜暂缓：…｜阻塞：…`。没有事项填“无”，不要只将状态写进文件。阶段转换、开始耗时工作、出现阻塞、等待选择和交付时更新这一行；长任务有实质变化就报告。等待确认时指出正在等哪项选择，把最早可看的草图或预览直接交给用户。

在上述节点同步创建或更新项目的 `.feelmuse/session.md`；短任务可以只有几行。记录：

- 当前阶段、这一阶段要验证的假设、下一步；
- 已完成的工作和可复查的证据，如原型路径、截图、实测视口；
- 已确认的决定及依据，分别标明用户选择、明确委托下的代理选择和仍待确认的事项；正在等草图选择时，保存各选项的构图差异，让下个会话能理解“选 B”；
- 暂缓工作及恢复条件，阻塞原因及解除条件。

例如：`Visualize & Align｜正在等首屏构图选择｜已完成：方向已选“声音地图”，已展示 A/B 草图｜暂缓：下载底图与音频｜阻塞：待用户选择常驻卡或点选展开`。用户选 B 后再更新为“草图 B 已确认”；实际原型尚未确认时保留该状态。恢复时从第一个未通过的检查点继续。若项目不可写，在 CLI 说明记录未能保存，不声称已持久化。
