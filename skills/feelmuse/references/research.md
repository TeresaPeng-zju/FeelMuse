# 从参考中提取什么

优先在浏览器打开实际页面，亲手滚动、悬停、点击、反向操作。记录 URL、页面区域、视口和状态，足够让人重现。无指定参考时，围绕产品的某个表达难题找一两个案例，例如“如何让访客看懂镜片层次”；不必为了列满风格收集作品。

先观察第一眼看到什么、文字与图像如何分配注意力、图片/视频/3D 在哪个时刻提供了什么信息。看交互要记录触发、起始状态、过程中什么固定和什么移动、结束与退出方式、触屏对应体验。需要时查 DOM、计算样式或运行行为。将“看到的效果”“可能的解释”“我们可用的实现”区分开。单张截图只支持静态判断；打不开或无法触发就写明缺口，必要时请用户给录屏或标出段落。

对每个参考保留一条可用笔记：**用户喜欢哪一处 → 实际观察 → 它解决的表达问题 → 自己产品中的应用 → 不继承什么**。只喜欢滚动，就无需采集整套美术。若 A 适合控制滚动节奏、B 适合安排文字、C 用视频展示过程，让它们分别支撑同一产品故事。若 A 要求停下来读而 B 要求连续穿行，在同一段同时使用会争夺注意力；具体建议保留哪一种，并按交互规则判断是否要确认。

不复制第三方品牌素材、图像、文案、代码或有辨识度的设计组合。用自有内容重新决定主体、构图、字体、配色、运动幅度与节奏。检验方法：拿掉参考品牌后，这个动作是否仍能帮助访客理解当前产品？
