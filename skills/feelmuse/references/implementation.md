# 从画面到代码

在当前项目找到页面入口、样式边界、已有动效、依赖及测试命令。局部增强尽量只改对应组件，先确认原有滚动、指针与键盘逻辑如何配合。没有项目时选能呈现该设计的最小前端方案。优先用现有素材、CSS、SVG 与原生事件；没有单独服务或特定动效库的前置要求。

验证前用一句话限定范围，例如“只看点位能否成为首屏焦点，以及点选后试听卡如何出现”。先用已有素材或最小替身：几个模拟地点、一张简化 SVG 底图、程序生成并标为示意的波形，即可试构图与动效。不影响当前判断的真实音频、地图下载、数据接入、完整搜索与播放器列入暂缓。只有真实性本身决定假设能否成立时才获取所需的最小素材，并说明它要验证什么。

在受首屏确认约束的任务里，低风险效果也只接入关键区域原型。先向用户交付可看的结果；浏览器打不开就报告具体阻塞，保持待验收，不以代码检查替代视觉通过。其他任务的低风险效果可直接进入页面。涉及长距离固定、多层同步、视频定位、相机运动或未知设备性能时，先定义可观察的通过条件。例如“进入时标题可读，中段两层错速，离开后滚动自然释放，反向滚回起点”。用独立临时页面或开发路由只验证最难的一段，包含足以测试真实节奏的内容与前后滚动空间。先在浏览器看起点、中点、终点、回滚和窄屏，然后才决定能否迁回正式页面。原型会改变叙事时按 interaction.md 展示并等待选择。

保留同一种表达意图设计降级路径：若实时 3D 在手机上不稳，可用同角度分层静帧加短距离位移保住纵深；视频不可用时用海报帧与正文；减弱动态偏好下按阅读顺序静态呈现内容。不要靠隐藏正文或劫持页面滚动来驱动叙事。测试调整窗口、重复进入、触屏及键盘操作，清理监听与动画。正式页面复用已验证的机制，并再次检查与原页面内容的衔接。

占位与示意必须可识别、有稳定替换点，优先沿用项目的素材位置和加载方式。保持页面在资源缺失或动效停用时仍能阅读、导航和完成主要操作。
