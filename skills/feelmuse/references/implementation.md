# 从画面到代码

在当前项目找到页面入口、样式边界、已有动效、依赖及测试命令。局部增强尽量只改对应组件，先确认原有滚动、指针与键盘逻辑如何配合。没有项目时选能呈现该设计的最小前端方案。优先用现有素材、CSS、SVG 与原生事件；没有单独服务或特定动效库的前置要求。

低风险效果直接进入页面。涉及长距离固定、多层同步、视频定位、相机运动或未知设备性能时，先定义可观察的通过条件。例如“进入时标题可读，中段两层错速，离开后滚动自然释放，反向滚回起点”。用独立临时页面或开发路由只验证最难的一段，包含足以测试真实节奏的内容与前后滚动空间。先在浏览器看起点、中点、终点、回滚和窄屏，然后才决定能否迁回正式页面。原型会改变叙事时按 interaction.md 展示并等待选择。

保留同一种表达意图设计降级路径：若实时 3D 在手机上不稳，可用同角度分层静帧加短距离位移保住纵深；视频不可用时用海报帧与正文；减弱动态偏好下按阅读顺序静态呈现内容。不要靠隐藏正文或劫持页面滚动来驱动叙事。测试调整窗口、重复进入、触屏及键盘操作，清理监听与动画。正式页面复用已验证的机制，并再次检查与原页面内容的衔接。

占位与示意必须可识别、有稳定替换点，优先沿用项目的素材位置和加载方式。保持页面在资源缺失或动效停用时仍能阅读、导航和完成主要操作。
