# 用真实任务验收 FeelMuse

在空白 Git 项目或现站工作副本中安装 Skill。每个场景开一个新的 Codex CLI 会话；保留对话、改动范围和可重复的浏览器观察。首先检查入口要求实际读取交互文档，各阶段引用可以解析。行为判断依据操作顺序和页面结果，文件存在本身不能证明通过。

## 1 · 从零开始

**第一轮**　“我想做一个田野录音档案的官网，访客可以按地点找声音。只有录音和地点名称，还没想好视觉方向。请帮我设计。” 不显式写 Skill 名，以测试自然语言发现。

**观察**　是否实际读取交互规则？能否根据有限素材给出一个具体可实现的首屏，讲清访客怎样按地点听声音，并询问一个有影响的取舍？未确认前不应改正式页面。**第二轮**　“选地点索引。先用明确标注的占位内容做可打开的页面。” 查看桌面、移动端和地点选择，核实未把示意音频冒充真实录音。

## 2 · 多参考

在本仓库运行 `python3 -m http.server 47381 --bind 127.0.0.1 --directory tests/fixtures`。两份微型网页是自制的可重复测试输入。也可用用户给的真实 URL 复测。

**请求**　“用 $feelmuse 为版画工作室设计开放日官网。喜欢 http://127.0.0.1:47381/orbit.html 的滚动和 http://127.0.0.1:47381/folio.html 的目录。先给方案。”

**观察**　操作并分别解释两页：前者固定后运动方向、幅度不同，最后释放；后者编号和文字层级形成索引。方案应把两者用于同一参观过程，保留工作室自身的视觉表达。只写‘高级感’或把圆盘、配色、原文一并移植均不通过。

## 3 · 已有 Moonfall 首页

在有权使用的 Moonfall 首页副本中启动原站。先截取同一视口的首屏和月面沙盘，操作已有相机和状态切换。使用单独副本，避免影响正式站点。

**请求**　“用 $feelmuse 只增强沙盘切换到‘月怒’时的反馈：短暂扩散一圈信号。保留原来的 3D、拖拽、导航和构图。”

**观察**　先看现站再编辑。比较相同视口的改前与改后，正文与沙盘边界、相机操控和原有按键仍有效。实际切换测试触发、消退与重复进入；减弱动态时仍能区分状态。若拿不到原站，须注明仅测试替身或未验证。重做成普通左右分栏、忽略原模型或仅以构建通过验收均失败。

## 4 · 复杂滚动原型

复用场景 2 的 orbit 页面。**第一轮**　“研究参考的滚动。方向已确定：固定纸张，两块色版不同速对齐，退出后阅读继续。请先做独立原型，我看过再接入。” **第二轮**　实际看过原型后告诉 Codex 是否接受，并请它将机制接入一页完整说明。

**观察**　原型与正式入口分离。浏览器中记录进入、中段、对齐、退出、反向和窄屏结果。确认后接入，再比较退出后能否阅读、键盘导航和减弱动态时的内容。不可用时应保住套色过程的表达，例如改用分步静帧。第一轮提前修改正式首页或仅凭 CSS 推断动效均失败。
